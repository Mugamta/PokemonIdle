# 스토리 트레이너 추가 계획 (관장 · 사천왕/챔피언 · 악의 조직 · 라이벌)

## 0. 목표와 원칙

- 야생 포켓몬 위주인 지금의 진행 흐름에 **스토리상 반드시 만나는 트레이너 전투**를 더한다.
- 방치형 게임이므로 **자동 전투로도 끝까지 진행할 수 있어야** 한다. 트레이너는 "벽" 역할을 하되, 반복 사냥으로 넘을 수 있어야 한다.
- 지금 있는 시스템(스테이지 순차 해금, 보스, 자동 전투, 특수 기능, 패배 시 회복)을 **최대한 재사용**하고, 새로 만드는 부분은 "상대 파티(여러 마리)"와 "스토리 진행 플래그" 두 가지로 줄인다.
- 트레이너 데이터는 코드와 분리된 **데이터 파일**로 둔다. 지방별 내용은 데이터만 추가하면 늘어나게 한다.
- 캐릭터(이름·대사·외형)는 **원작 재현**으로 만든다. 원작 관장·챔피언·조직의 이름과 외형을 따르고, 역할(관장 8명, 사천왕+챔피언, 악의 조직 하급단원 → 간부 → 보스)과 포켓몬 종·타입 테마도 원작대로 둔다.

## 1. 현재 구조 요약 (변경 지점 파악)

| 영역 | 현재 | 트레이너 추가 시 문제 |
|---|---|---|
| 상대 | `enemy: WildPokemon` 한 마리 ([game.ts](../src/stores/game.ts)) | 트레이너는 1~6마리 파티가 필요함 |
| 보스 | 일반 포켓몬을 `BOSS_DEFEATS`(10)마리 쓰러뜨리면 `makeBoss()` | 트레이너는 정해진 팀을 쓰고, 등장 조건도 다름 |
| 클리어 | `onBossCleared()` → `clearedStages` → 다음 스테이지 해금 | 트레이너를 이겨야 열리는 "관문"이 필요함 |
| 지방 | `arrive()` 하면 바로 해금되고 특수 기능도 함께 해금, 자유롭게 이동 | 특수 기능 해금 시점을 챔피언 격파로 옮겨야 함 |
| 스테이지 해금 | 이전 스테이지를 클리어하면 열림 | 필드기술 조건이 추가되고, 잠긴 스테이지는 건너뛰어야 함 |
| 전설 | 출현 데이터에 없음 | 출현 자체를 새로 만들어야 함 |
| 지도 | `town` 장소는 스테이지가 아니라 지형지물일 뿐 | 체육관·리그가 마을에 있으므로 마을에도 이벤트를 붙여야 함 |
| 연출 | `BattleScene`의 보스 등장 연출, 로그의 `boss` 표시 | 트레이너 등장 연출, 남은 포켓몬 수 표시 |

## 2. 데이터 모델

### 2-1. 트레이너 정의 — `src/data/trainers/types.ts`

```ts
export type TrainerClass =
  | 'gym'          // 관장
  | 'elite'        // 사천왕
  | 'champion'     // 챔피언
  | 'rival'        // 라이벌
  | 'grunt'        // 악의 조직 하급단원
  | 'admin'        // 악의 조직 간부
  | 'villainBoss'  // 악의 조직 보스

export interface TrainerMon {
  species: string
  level: number
  /** 지정하지 않으면 wildMoveset 규칙으로 자동 */
  moves?: string[]
  item?: string
  ability?: string
  nature?: string
  /** 개체값 고정치 (기본: 관장 20, 사천왕 이상 31) */
  iv?: number
  /** 이 포켓몬이 쓰는 특수 기능 (칼로스 이후 지방 에이스 등) */
  gimmick?: 'mega' | 'z' | 'dynamax' | 'tera'
  teraType?: string
}

export interface Trainer {
  id: string                // 'kj-gym-1'
  name: string              // 원작 이름
  class: TrainerClass
  title?: string            // '바위 타입 관장' 등 표시용
  team: TrainerMon[]
  /** 전투 중 회복약 사용 횟수 (원작 트레이너처럼) */
  potions?: number
  reward: {
    money: number
    items?: { id: string; n: number }[]
    badge?: string          // 배지 id
    flag?: string           // 이기면 켜지는 스토리 플래그
  }
  text: { intro: string; defeat: string; win?: string }
  /** 재대결 시 레벨 보정 (반복 모드) */
  rematch?: { levelBonus: number; reward: number }
}
```

### 2-2. 스토리 이벤트 배치 — `src/data/story/<지방>.ts`

트레이너를 **어디서, 어떤 조건으로** 만나는지만 정의한다.

```ts
export interface StoryEvent {
  id: string
  trainer: string | string[]          // 여러 명이면 연전 (사천왕 → 챔피언)
  /** 붙는 위치: 스테이지 이름 또는 마을 이름 */
  at: { stage: string } | { town: string }
  /** 관문: 이기기 전에는 다음 스테이지(들)가 잠김 */
  gate?: { blocks: string[] }         // 잠그는 스테이지 이름
  /** 등장 조건 */
  requires?: { flags?: string[]; badges?: number; cleared?: string[] }
  /** 연전 중 회복 불가 (리그) */
  gauntlet?: boolean
  /** 하급단원처럼 스테이지에 랜덤 출현 */
  random?: { rate: number; max: number }
}
```

- `Region`에 `story?: StoryEvent[]`를 추가한다 ([stages.ts](../src/data/stages.ts)의 `RAW`).
- 관문은 **스테이지 순서(`stageUnlocked`)에 조건을 하나 더하는 방식**이라 기존 해금 로직을 크게 바꾸지 않는다.

## 3. 전투 엔진 변경 (핵심 작업)

현재 `enemy`는 그대로 "지금 나와 있는 상대 포켓몬"으로 쓰고, **파티는 `trainerBattle.party`에서 관리**한다. 이렇게 하면 기존의 데미지 계산, 특성, 특수 기능 코드를 거의 그대로 쓸 수 있다.

1. **`WildPokemon` 확장**: `boss?: boolean` 옆에 `trainer?: string`(트레이너 id)을 추가한다. `enemyBattler()`는 이름 앞에 "보스/야생" 대신 `"<트레이너 이름>의 "`를 붙인다.
2. **`startTrainerBattle(event)`**: `TrainerMon` → `WildPokemon` 변환(`makeTrainerMon`)을 하고, 첫 포켓몬으로 `startBattle()`을 호출한다.
3. **`onEnemyFainted()` 분기**
   - 트레이너 전투이고 남은 포켓몬이 있으면: 경험치만 주고(트레이너 보정 ×1.5) 다음 포켓몬을 내보낸다(`sendNextTrainerMon`). 상금, 도구, `defeats` 증가는 하지 않는다.
   - 마지막 포켓몬이면 `onTrainerDefeated()`: 상금, 배지, 플래그, 보상 아이템을 주고 관문을 연다. 연전이면 다음 트레이너로 넘어간다.
4. **금지 행동**: 트레이너 포켓몬에는 몬스터볼을 못 쓴다. 기존 `!e.boss` 검사에 `!e.trainer`를 더한다.
5. **상대 AI**
   - 교체: 1단계에서는 하지 않는다(쓰러지면 다음 포켓몬만 나옴).
   - 회복약: HP 25% 이하일 때 `potionsLeft`가 남아 있으면 한 턴을 써서 회복한다.
   - 특수 기능: `gimmick` 지정 포켓몬이 처음 나올 때 발동한다. `gimmicks.ts`에 상대용 적용 함수를 추가한다.
6. **패배/포기**: `goRecover()`가 `trainerBattle`을 비운다. 관장전은 다시 도전하면 처음부터 시작하고, 리그 연전은 사천왕 1번부터 다시 시작한다.
7. **자동 전투**: 관문 트레이너는 `stageMode === 'advance'`이고 관문 스테이지를 클리어했을 때 자동으로 도전한다. 연속 패배 시 무한 루프를 막기 위해, 패배 후 **그 스테이지에서 일반 포켓몬 N마리를 잡아야 다시 자동 도전**한다(기존 `onBossFailed` 방식과 같음).

## 4. 클래스별 설계

### 4-1. 관장 (지방당 8명, 관동·성도는 16명)

- **위치**: 각 체육관 마을에 가장 가까운 "다음 구간 진입 스테이지" 앞에 관문으로 둔다. 마을은 지도에서 클릭할 수 있는 이벤트 지점이 된다(`RegionMap`의 `town`에 마커 표시).
- **팀**: 타입 테마 2~6마리. 레벨은 **관문 직전 스테이지의 보스 레벨 +2~5**를 기준으로 데이터를 만들 때 계산한다(`scripts/`에 보조 스크립트를 둔다).
- **배지 효과**:
  - 각 배지는 대응하는 비전기술의 사용 허가 역할을 한다(§4-7). 예: ○번째 배지 = 파도타기.
  - 배지 8개(관동·성도는 16개)를 모으면 리그(챔피언로드 이후)에 들어갈 수 있다.
- **재대결**: 반복 모드에서 하루 1회 등, `rematch.levelBonus`만큼 레벨을 올려 돈과 아이템 보상을 준다.

### 4-2. 사천왕 + 챔피언

- **위치**: 각 지방 `챔피언로드` 다음, 리그 마을(관동·성도는 석영고원)에 둔다.
- **연전**: 5명을 연속으로 상대하고, **중간에 센터 회복이 없다**(`gauntlet: true`). 가방 아이템 자동 사용은 허용한다.
- **보상**: 챔피언을 처음 격파하면 그 지방의 `champion:<지방 key>` 플래그가 켜지고, 다음 두 가지가 열린다.
  1. **그 지방의 전투 특수 기능 해금** (§4-5)
  2. **그 지방의 전설 포켓몬 포획 가능** (§4-6)
- 그 밖의 보상: 명예의 전당 기록(클리어 파티), 고급 상점 품목
- 지방 간 이동은 지금처럼 자유롭다. 챔피언 격파는 다음 지방 해금 조건이 아니다.
- 칼로스 이후 지방의 사천왕·챔피언 에이스는 그 지방의 특수 기능을 쓴다. 플레이어보다 먼저 보여 주는 셈이다.

### 4-5. 전투 특수 기능 해금 조건 변경

- **현재**: 지방에 들어가는 순간(`arrive()` → `unlockedRegions`) 해금된다. 판정은 getter `gimmickUnlocked` 하나뿐이다([game.ts:616](../src/stores/game.ts#L616)).
- **변경**: 그 지방 챔피언을 격파해야 해금된다.
  ```ts
  gimmickUnlocked: (s) => (g) => REGIONS.some((r) => r.unlocks === g && s.storyFlags.includes(`champion:${r.key}`))
  ```
- `arrive()`의 "들어와 ○○이 해금되었다" 로그는 "이 지방 챔피언을 이기면 ○○을 쓸 수 있다" 안내로 바꾸고, 해금 로그는 `onTrainerDefeated()`(챔피언)로 옮긴다.
- 화면에서 쓰는 곳은 getter만 보고 있다(BattleControls, BattleTab, ShopTab). 그래서 getter만 바꾸면 되고, 잠금 안내 문구만 고친다.
- 상점의 특수 기능 관련 품목(메가스톤, Z크리스탈, 테라피스 등)은 **구매는 허용하고 사용만 잠근다**. 또는 해금 전까지 숨길 수도 있다(결정 필요).

### 4-6. 전설 포켓몬

- **현재**: 출현 데이터(`encounters/*.json`)에는 전설 포켓몬이 없다. `special`은 대량발생 같은 특수 출현일 뿐이다. 따라서 전설 출현 자체를 새로 만들어야 한다.
- **데이터**: `src/data/story/<지방>.ts`에 전설 출현을 정의한다.
  ```ts
  export interface LegendEncounter {
    species: string
    level: number
    at: { stage: string }            // 출현 스테이지 (예: 쌍둥이섬, 무인발전소, 은빛산 등)
    requires: { flags: string[] }    // 기본: [`champion:<지방>`], 필요하면 비전기술도 (§4-7)
    /** 쓰러뜨리거나 도망갔을 때 다시 나오기까지 걸리는 시간 (방치형이라 영구 소멸 대신 재출현) */
    respawnMs: number
  }
  ```
- **흐름**: 챔피언을 격파하면 출현 스테이지에 "전설의 기운" 마커가 생긴다. 그 스테이지에서 일반 포켓몬을 일정 수 쓰러뜨리면 보스 대신 전설 포켓몬이 나온다(기존 `bossReady` 흐름을 그대로 쓴다).
- **포획**: 전설 포켓몬에는 볼 사용을 허용한다(보스·트레이너와 다름). 포획률은 원작 `capture` 값을 따른다. 쓰러뜨리면 `respawnMs` 뒤에 다시 나온다. 한 번 잡으면 그 스테이지에서는 더 나오지 않는다.
- 자동 전투에서는 전설 포켓몬에게 자동으로 볼을 던질지 설정으로 정한다.
- 히든 지방(히스이)의 `requiresCaught: 'arceus'` 조건도 이 시스템으로 아르세우스를 잡을 수 있어야 성립한다. 아르세우스 출현 위치는 정해야 한다.

### 4-7. 비전기술(필드기술)에 따른 진행 잠금

**데이터** — 스테이지마다 필요한 필드기술을 적는다.
```ts
export type FieldMove =
  | 'cut' | 'flash' | 'surf' | 'strength' | 'rock-smash'
  | 'waterfall' | 'whirlpool' | 'fly' | 'rock-climb' | 'defog' | 'dive'
// stages.ts RAW 항목에 추가
fieldReq?: Record<string /* 스테이지 이름 */, FieldMove[]>
```
- 수상 스테이지(`kind: 'water'`)는 기본으로 `surf`가 필요하다. 육지 스테이지는 개별 지정한다.
  예: 블루시티동굴 = surf, 챔피언로드 = strength·surf, 소용돌이섬 = whirlpool, 얼음샛길 = strength, 은빛산 = surf·waterfall 등. 어디에 무엇이 필요한지는 원작 맵 조건을 조사해 표로 만든다.
- 알로라(라이드포켓몬), 가라르(자전거), 팔데아(라이드 능력)는 비전기술이 없다. 같은 `FieldMove` 키에 **지방별 표시 이름**만 바꿔 쓴다(예: 알로라의 `surf` = "라프라스 라이드").

**얻는 방법** — 스토리 보상으로 받는다.
- `Trainer.reward` / `StoryEvent`에 `fieldMove?: FieldMove`를 추가한다. 관장 격파나 조직 간부 격파 같은 스토리 시점에 해금된다.
- 해금 조건은 **비전머신 획득 + 해당 배지**로 한다(원작 방식).
- 파티에 그 기술을 아는 포켓몬이 있어야 하는지는 결정이 필요하다(§9).
  - 추천: **필요 없음**. 방치형에서 기술칸 하나를 비전기술로 채우는 "비전 셔틀" 부담을 없앤다.
- 공중날기: 지금은 파티에 `fly`를 아는 포켓몬이 있으면 순간이동과 패배 지점 복귀가 된다(`canFly`). 이 조건을 필드기술 해금으로 바꾼다.

**스테이지 해금 로직 변경** (`stageUnlocked`)
- 조건이 부족한 스테이지는 잠긴다(지도에 필요한 기술 아이콘을 표시한다).
- 지금은 "이전 스테이지를 클리어하면 다음 스테이지 해금"이라 잠긴 스테이지가 끼어 있으면 진행이 끊긴다. 그래서 **조건이 부족한 스테이지는 건너뛰고** 그다음 갈 수 있는 스테이지를 이전 스테이지 기준으로 연다.
  - 나중에 조건을 갖추면, 건너뛴 스테이지는 그 직전 스테이지를 클리어한 상태라면 바로 열린다.
  - `reorderWater()`가 수상 스테이지를 레벨 기준으로 뒤로 미는 것과도 충돌하지 않는다.
- 전진 모드 자동 이동(`onBossCleared` → next)도 잠긴 스테이지를 건너뛴다.
- 패배 후 돌아갈 길목 계산(`goRecover`)도 갈 수 없는 스테이지는 제외한다.

### 4-3. 악의 조직

지방마다 원작 조직을 재현한다. 3단계 구조이다.

1. **하급단원** (`grunt`): 지정 스테이지에서 야생 대신 일정 확률(`random.rate`, 예: 8%)로 등장하며, 스토리 구간당 `max`회까지 나온다. 1~3마리를 쓰고, 상금이 야생보다 많다.
2. **간부** (`admin`): 아지트·탑 같은 특정 스테이지의 관문이다. 하급단원을 `max`회 다 쓰러뜨리면(`requires.flags`) 등장한다.
3. **보스** (`villainBoss`): 스토리 클라이맥스 스테이지의 관문이다. 이기면 스토리 플래그가 켜져 다음 구간이 열리고, 비전머신 같은 보상을 받는다. 전설 포켓몬 해금은 챔피언이 담당한다(§4-6).

- 스토리 진행 표시: 스테이지 탭에 "조직 활동 중" 아이콘을 띄우고, 로그에 짧은 대사를 남긴다.
- 조직 테마 아이템 보상: 하급단원 → 회복약 소량, 간부 → 기술머신, 보스 → 마스터볼급 희귀 보상(지방당 1회).

### 4-4. 라이벌

- 지방당 3~5회 등장하며, 특정 스테이지 진입 시 관문으로 나온다.
- 팀에 **플레이어 스타팅의 상성 우위 스타팅 계열**을 넣는다. `starters.ts`를 보고 고르며, 진화 단계는 레벨에 맞춘다.

## 6. 밸런스 기준

- 관장 에이스 레벨 = 관문 직전 스테이지 `levels().max + 3`
- 관장 팀 평균 레벨 = 에이스 −2~3
- 사천왕 = 챔피언로드 최고 레벨 +3~6, 챔피언 = 사천왕 +2~3
- 하급단원 = 해당 스테이지 평균 레벨
- 트레이너 포켓몬 경험치 ×1.5 (원작 트레이너 보정), 상금 = `기본 단가(클래스별) × 최고 레벨`
- 난이도 `hard`: 트레이너 개체값 31, 숨겨진 특성, 회복약 +1
- 레벨 보조 스크립트(`scripts/trainerLevels.ts`)가 encounters JSON에서 기준 레벨을 계산해 출력한다. 데이터는 그 값을 보고 직접 적는다.

## 7. 저장 데이터 이전

- 새 필드는 모두 기본값으로 채우며 `SAVE_VERSION`은 2로 올린다.
- **이미 지나간 관문은 열어 둔다**: 저장 데이터를 불러올 때 `clearedStages` 기준으로 관문 뒤 스테이지를 이미 클리어했으면 진행은 막지 않는다. 다만 트레이너는 "미격파"로 남겨 선택 도전으로 둔다. 배지도 실제로 이겨야 받는다.
- **이미 클리어한 필드기술 잠금 스테이지**: 클리어 기록이 있는 스테이지는 계속 갈 수 있다. 아직 클리어하지 않은 잠금 스테이지는 새 규칙을 따른다.
- **이미 해금된 특수 기능**: 기존 저장 데이터는 지방에 들어가기만 해도 특수 기능이 해금되어 있다. 이를 다시 잠글지(챔피언 격파 필요), 그대로 둘지 정해야 한다(§9).

## 8. 단계별 작업 순서

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **1. 엔진** | `Trainer`/`StoryEvent` 타입, `trainerBattle` 상태, 여러 마리 상대 전투, 승리/패배 처리, 볼 금지 | 테스트용 트레이너 1명(3마리)을 수동 도전해 이길 수 있음 |
| **2. 관문·자동 전투** | `stageUnlocked`에 관문 조건 추가, 자동 도전과 패배 쿨다운 | 자동 전투만으로 관문을 넘거나, 막히면 반복 사냥으로 전환됨 |
| **3. 필드기술 잠금** | `FieldMove` 데이터, 스테이지별 필요 기술 표, 잠긴 스테이지 건너뛰기, `canFly` 교체 | 파도타기가 없으면 수상 스테이지가 잠기고, 진행이 끊기지 않음 |
| **4. 관동·성도 관장 16명 + 배지** | 관장 데이터, 배지 → 비전기술 연결, 저장 데이터 이전 | 새 게임에서 1-1부터 배지 16개까지 진행 가능 |
| **5. 리그 + 특수 기능 해금** | 사천왕+챔피언 연전, 명예의 전당, `gimmickUnlocked`를 챔피언 플래그 기준으로 변경 | 연전 중간에 지면 처음부터 다시 시작하고, 챔피언을 이기면 특수 기능이 해금됨 |
| **6. 전설 포켓몬** | `LegendEncounter` 데이터, 챔피언 플래그로 출현, 포획·재출현 | 챔피언을 이긴 뒤 전설 포켓몬을 잡을 수 있음 |
| **7. 악의 조직 + 라이벌** | 랜덤 출현 하급단원, 간부·보스 관문, 라이벌 | 관동·성도 조직 스토리 한 바퀴 완료 |
| **8. UI 정리** | 등장 연출, 트레이너 카드, 지도 마커(관문·필드기술·전설), 실루엣 아이콘 | — |
| **9. 다른 지방 확장** | 호연~팔데아 데이터, 상대 특수 기능 사용, 라이드 계열 필드기술 이름 | 지방마다 데이터 파일만 추가하면 됨 |

1~3단계가 끝나면 나머지는 대부분 데이터 작업이다.

## 9. 결정이 필요한 사항

1. **필드기술을 쓰려면 파티에 그 기술을 아는 포켓몬이 있어야 하는지** (추천: 필요 없음. 비전머신 + 배지만 있으면 됨)
2. **기존 저장 데이터의 특수 기능**: 다시 잠금 / 그대로 유지
3. **특수 기능 관련 상점 품목**: 해금 전 구매 허용 / 숨김
4. **전설 포켓몬을 쓰러뜨렸을 때**: 재출현(추천, 방치형) / 영구 소멸
5. **관장 재대결 방식**: 하루 1회 / 쿨타임 / 무제한
6. **트레이너 그림**: 실루엣 아이콘으로 시작할지, 처음부터 원작 재현 도트를 준비할지
